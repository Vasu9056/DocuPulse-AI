
================================================================================
1. EXECUTIVE OVERVIEW: WHAT IS DOCUPULSE AI?
================================================================================
• THE PROBLEM:
  - Standard LLMs (ChatGPT, Claude) have knowledge cutoffs and hallucinate old,
    deprecated syntax for fast-moving frameworks (Next.js 15, Bright Data SDK, 
    LangChain v0.3, Supabase).
  - Documentation websites frequently redesign their frontend layout (e.g., 
    migrating from Docusaurus to Mintlify/Nextra), which breaks standard CSS scrapers 
    and corrupts downstream vector embeddings.

• THE SOLUTION:
  - DocuPulse AI uses Bright Data Scraper Studio to continuously crawl documentation 
    pages into clean markdown and API signatures.
  - When target doc sites change their DOM, Scraper Studio's Self-Healing Engine 
    auto-repairs selectors from natural language prompts with Zero Vector Drift.
  - A high-precision RAG (Retrieval-Augmented Generation) pipeline grounds AI 
    answers with verified, clickable source citations.

3. STEP-BY-STEP BACKEND & VECTOR RAG PIPELINE
================================================================================

• STEP 1: MARKDOWN CHUNKING & PRE-PROCESSING
  - Long documentation pages (3,000–5,000 words) are split into semantic chunks 
    (~300 to 500 words each) using Markdown Header splitting (## and ###).
  - Each chunk gets a unique ID, text snippet, and metadata (doc_title, url, version).

• STEP 2: VECTOR EMBEDDINGS & STORAGE (VECTOR DB)
  - Each text chunk is passed through an Embedding Model (e.g. OpenAI 
    `text-embedding-3-small` or Gemini Embeddings) to convert text into a 
    1536-dimensional numerical vector.
  - Vectors + metadata are stored inside a Vector DB (ChromaDB, Pinecone, or SQLite).
  - Total indexed chunks across target libraries: ~18,420 chunks.

• STEP 3: USER QUERY & COSINE SIMILARITY SEARCH
  1. User asks a question in the Chat UI.
  2. Backend generates an embedding vector for the user's question.
  3. Vector Database performs Cosine Similarity Search to retrieve the Top 2–3 
     most relevant chunks (e.g. Chunk #bd_dca_092 with 98.6% Cosine Similarity).

• STEP 4: GROUNDED PROMPT INJECTION (STRICT LLM PROMPTING)
  - Backend dynamically constructs a strict system prompt combining the retrieved 
    documentation chunks and user question:
    "Answer strictly based ONLY on the provided scraped documentation context. 
     Do not invent deprecated methods."

• STEP 5: LLM SYNTHESIS & OUTPUT FORMATTING
  - LLM synthesizes an accurate technical explanation and code snippet.
  - Backend returns the answer markdown along with citation metadata (title, URL, 
    similarity score, exact scraped paragraph).

5. HOW SELF-HEALING PROTECTS THE RAG PIPELINE (ZERO VECTOR DRIFT)
================================================================================
• SCENARIO: 
  Next.js or Bright Data redesigns their documentation website (e.g. migrating 
  HTML structure from Docusaurus `.theme-doc-markdown` to Mintlify `article.prose-doc`).

• WHAT HAPPENS WITH TRADITIONAL SCRAPERS:
  1. The scraper crashes or returns 0 rows (null content).
  2. The vector database receives empty chunks.
  3. The RAG AI copilot starts hallucinating or giving outdated answers.

• HOW BRIGHT DATA SCRAPER STUDIO PREVENTS THIS:
  1. Scraper Studio detects that selector `.theme-doc-markdown` returned empty data.
  2. Scraper Studio re-evaluates the natural language field prompt:
     "Main technical documentation article body and code snippets".
  3. It automatically derives the new resilient selector:
     `article.prose-doc, .content-wrapper main`
  4. 4,200 pages and 18,420 vector chunks are recovered with Zero Vector Drift 
     and Zero Downtime.
  5. Developers using DocuPulse AI never experience a single broken citation!
